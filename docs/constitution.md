# 工程宪法（Constitution）

> 平台级不可妥协原则 · v1 · 2026-07-31 · 修宪=独立 ADR（superseded 留痕）
> 被 CLAUDE.md @import；全部 skill/agent/评审共同遵守。每条：原则 + 为什么 + 可执行检查。

- **C1 未过门禁不进下一段**。为什么：门禁是人介入边界，绕过=流程失效。检查：各阶段 skill 第 0 步跑探针 `--gate-only`，退出码 64 即拒绝启动。
- **C2 能用可执行验证的，绝不用"我觉得对了"**。为什么：只有可执行验证才真正约束 agent。检查：每阶段制品有 check-*.sh 且 skill 交付前强制跑。
- **C3 安全边界只认服务端强制**。hooks/CLAUDE.md 是本地快反馈与建议；硬策略=permission system + 受保护分支 + CI required checks。为什么：官方明示 hook 过滤 best-effort/fail-open。检查：M3 起 demo 仓分支保护与 required checks 配置存在（`gh api` 探针）。
- **C4 产物是真相，工具是适配**。specs/ 与 docs/ 放仓库根；`.claude/` 只放 skill/agent/hook/配置，不放业务真相。为什么：防供应商锁定（AGENTS.md 已入 LF 中立治理）。检查：目录规范探针（`.claude/` 下仅允许 skills|agents|hooks|rules|settings*）。
- **C5 一事一 ADR，决策必含 ≥2 真实备选，不可变只追加**。为什么：没有备选的"决策"是"决定"；改写历史=销毁审计。检查：check-design.sh ADR 规则（备选 ≥2、后果段存在、编号连续）。
- **C6 文档随 PR 演进，spine ≤300 行**。为什么：大文档必腐化（BMAD 教训）。检查：spine 行数探针；架构变更 PR 必须同步改 spine（评审项）。
- **C7 全部交付物中文**。为什么：受众定位（企业培训中文为主）。检查：交付物抽查（评审项）。
- **C8 一切工作从门禁⓪开始**。新功能、重构、大改都先立项（prfaq），禁止"顺手做大事"。为什么：无 appetite 的工作没有熔断线。检查：`specs/` 下无对应 feature 的大改动=评审阻断。**紧急通道**：生产事故/安全修复可先行动，但须在 48h 内限时补做 prfaq（标 retroactive-emergency）+ 审计记录 + 回归测试——事后补票，不是免票。
- **C9 平台仓自包含**。零个人绝对路径/私有依赖。为什么：对外分发的底线。检查：grep 探针零命中（M1 起挂常跑）。
- **C10 appetite 熔断：到期砍范围，不展期**。为什么：没有熔断线的项目烂尾。检查：prfaq 含 Appetite 与砍序；超期时门禁记录里必须出现砍范围决定。
- **C11 每条需求/设计可追溯，零孤儿**。为什么：孤儿=没人要过的工作。检查：PRD/spec 追溯表探针 + architect 预审。
- **C12 AI 产出按风险分档过对抗评审**。高=异构评审+人审；中=可执行验证+单 lens；低=抽查+探针；门禁打回 ≥2 次自动升档。为什么：同一模型自查有系统性盲区（本平台调研 Round 1 实证）。检查：高风险制品的评审记录块含异构辩论矩阵。
- **C13 探针自身必须能证伪**。每个 check-*.sh 须对至少一个构造的坏样本 FAIL。为什么：只对好样本 PASS 的探针是安慰剂。检查：探针负样本测试（`tests/probe-negative/`，M1 落地）。
- **C14 批准可归因，执行者不得自批**（2026-07-31 修宪，ADR-011）。任何门禁的批准者必须是可归因的人类身份；产出该制品的 agent/自动化不得为其填写批准。为什么：AI 自批=审计造假，摧毁六门禁全部公信力。检查：试点模式=门禁块批准人必为人类署名（评审抽查）；企业模式=服务端 review 事件 actor ≠ PR author（分支保护规则，M3）。
- **C15 最小权限与供应链固定**（2026-07-31 修宪，ADR-011）。密钥不入仓、客户代码不外发第三方、CI 第三方 Action 锁定版本（SHA pin）、平台依赖显式声明并经 doctor 检查。为什么：咨询场景碰客户代码，供应链事故=商誉终结。检查：secret 扫描探针（M3 入 CI）；workflows 中 Action 引用含 SHA（探针 grep）；`e2e doctor` 前置清单（ADR-010）。
