# ADR-010：显式工具前置声明 + `e2e doctor`（细化 ADR-005 边界）

- 状态：accepted（细化 ADR-005，不推翻其 bash 选型）
- 日期：2026-07-31
- 关联：异构评审阻断#8 · SPEC-4/14/17 · 宪法 C15

## 背景与驱动力

异构评审指出 ADR-005"bash+零依赖"的前提与设计不符：`gh` 非 macOS 内置；JSON 棘轮、GitHub 状态解析、跨栈体检都超出 grep 量级。"零依赖"若名不副实，受众第一次跑就翻车。

## 备选方案

### 选项 A：坚持字面零依赖（所有功能都用内置工具硬写）
- 优点：口号干净
- 代价：bash 手搓 JSON/API 解析=不可维护的巫术代码；实际做不到（gh 无替代）

### 选项 B：放弃 bash，整体转 python/node
- 优点：表达力解决
- 代价：ADR-005 已论证过的安装摩擦回来了；推翻昨天的决策需要更强证据（评审并未主张整体推翻）

### 选项 C：**边界收窄 + 前置显式化**：bash 只做薄编排与简单结构探针（grep/comm 量级）；前置分层声明——基础层（git、Claude Code，本地全流程必需）/ 远程层（gh，门禁③服务端校验与 CI 需要）/ 目标栈层（demo 技术栈的 lint/test 工具）；`e2e doctor` 命令逐层检查并给安装指引；ratchet 基线弃 JSON 改**行式文本**（一行一 violation id，`sort`+`comm` 做集合差——纯内置工具）；缺前置时可预期降级（明确报错+指引，不静默错行为）
- 优点：ADR-005 的低摩擦保住（基础层真零依赖）；复杂需求各有出口；doctor 本身是受众体验加分项
- 代价：多一个 doctor 命令（M1 一次性 ~50 行）

## 决定

选 C。决定性理由：把"零依赖"改成诚实的"分层前置+doctor 自检"，既不巫术也不翻车。

## 后果

- ✅ SPEC-14 基线格式改行式文本（集合差可用 comm）；SPEC-4 的 gh 依赖显式标注远程层
- ✅ 手册"前置条件"节有了权威来源
- ⚠️ ADR-005 的"零依赖"表述由本 ADR 限定为"基础层零额外安装"
- 可复议条件：单探针复杂度超界时按 ADR-005 原有条款单独升 python
