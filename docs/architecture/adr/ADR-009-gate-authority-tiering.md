# ADR-009：门禁权威载体分级（supersedes ADR-004）

- 状态：accepted（取代 ADR-004；ADR-004 正文保留不改，状态由本文件宣告）
- 日期：2026-07-31
- 关联：异构评审阻断#5 + 单点风险 · 宪法 C3/C14 · SPEC-1~4/19

## 背景与驱动力

异构评审（GPT lens）指出单点风险：**可编辑 Markdown 门禁记录证明不了"人批"**——agent 可以自己填批准人，未合并分支还能改写历史。若企业不认这份审计证据，"六门禁/不可绕过/可审计"三个核心卖点同时失效。ADR-004 只在"文本 vs 结构化"里选，遗漏了两个备选（制品内结构化块 / per-feature 事件日志），更漏了真正的维度：**留痕 vs 防伪是两种不同强度的需求**。

## 备选方案

### 选项 A：维持 ADR-004（文本块是唯一账本）
- 优点：零改动
- 代价：单点风险原样存在；对企业受众讲不出防伪故事

### 选项 B：全面转服务端（所有门禁都以 PR review/check 事件为账本）
- 优点：防伪最强（actor/时间/SHA/URL 服务端记录，不可篡改）
- 代价：单人试点/离线场景每道门禁都要开 PR——流程重到没人用；⓪①等文档门禁强绑 PR 语义别扭

### 选项 C：**权威载体分级**——两种运行模式显式区分：
- **试点/单人模式**：文本块=流程留痕 + 探针校验格式；手册与制品页脚**诚实标注"流程提示，非防伪审批证据"**
- **企业强制模式**（M3 起可开）：门禁权威载体=受保护分支的 PR review/check 事件（记录 actor、时间、commit SHA、事件 URL）；Markdown 块降为**可读投影**，CI 校验投影与事件一致；批准者≠制品作者（宪法 C14，分支保护强制）
- 优点：试点轻量不受损；企业故事完整且技术上站得住（服务端事件正是 C3 的语义延伸）；两种模式的边界本身就是培训内容
- 代价：企业模式多一套投影一致性校验（M3 实现，one-off）

## 决定

选 C。决定性理由：留痕与防伪是两档需求，用一套载体硬扛两档正是 ADR-004 被击穿的原因；分级后各档各得其所。

## 后果

- ✅ 单点风险出清：企业模式的审批证据在服务端，agent 摸不到
- ✅ 试点不加重；"诚实标注"本身避免了对客户的过度承诺（咨询信誉）
- ⚠️ SPEC-1~4 语义修订为"试点模式账本"；企业模式投影校验入 M3（SPEC-19 关联）
- 可复议条件：官方推出原生审批/签名机制时重估（新 ADR）
