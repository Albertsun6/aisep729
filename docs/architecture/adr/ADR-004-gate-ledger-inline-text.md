# ADR-004：门禁账本采用"制品内文本块"，暂不引入结构化 gates.yaml

- 状态：superseded by ADR-009（2026-07-31 异构评审后分级重构；本文正文按 C5 保留不改）
- 日期：2026-07-31
- 关联：SR-1 门禁串锁 · PRD 移交-阶段2（本 ADR 即该移交项的裁决）· SPEC-1~3

## 背景与驱动力

门禁串锁靠读取上一制品的门禁记录。阶段0 实跑曾抓到格式漂移（模板/制品/探针三者不一致），暴露文本格式的脆弱性——需要正式决策存储形态。

## 备选方案

### 选项 A：制品内文本块（现状）——每制品尾部固定格式"门禁N 记录：批准人/决定/日期/备注"
- 优点：审计与制品同处一文件（看 prfaq 即见立项决定）；人类可读零工具；git 历史即审计链；探针 grep 即可校验
- 代价：格式脆弱（已实证漂移一次）；机器汇总（跨 feature 看板）需逐文件解析

### 选项 B：集中 gates.yaml（结构化账本，所有门禁记录入一个 YAML）
- 优点：机器可靠、看板/统计友好
- 代价：制品与决定分离（看 prfaq 不见批准，审计要跳文件）；多一个同步点（改制品忘改 yaml=新的漂移源）；yaml 解析对 bash 探针反而更重

### 选项 C：双写（文本块为准 + 归档时生成结构化索引）
- 优点：兼得可读与可汇总
- 代价：同步逻辑是新的 bug 面；试点期无机器消费方（demo 已定为赌场记录，非门禁看板）

## 决定

选 A，配三条硬化措施：①格式规范升为 spec 契约（SPEC-1~3）；②模板单一来源（templates/ 为准，探针与模板同 PR 改）；③门禁解析抽公共函数 `scripts/lib/gate.sh`（M1，消除三处各自 grep）。

## 后果

- ✅ 零新增复杂度；审计随制品走；探针已实证可拦（PENDING/64 行为）
- ⚠️ 跨 feature 汇总暂靠 `grep -r "决定："`——够试点用
- 可复议条件：出现机器消费方（门禁看板类工具、多 feature 并行 ≥5）→ 升级 C（新 ADR）
