# ADR-008：阶段能力交付采用"六件套定式"，定义文档为 SOP 权威

- 状态：accepted
- 日期：2026-07-31
- 关联：用户指令（2026-07-31 门禁①备注："后面的阶段都要做 skill"）· US-2~6 · 宪法 C2

## 背景与驱动力

每个生命周期阶段的能力怎么交付：只写文档不可执行（约束不了 agent）；只写 skill 无权威定义（漂移无对照）。阶段0 实跑证明：探针抓格式漂移、SOP 走查抓语义缺口——两者缺一不可。

## 备选方案

### 选项 A：仅 skill（SKILL.md 即全部）
- 优点：一处维护
- 代价：SOP 与执行耦合，改流程=改 prompt 无评审锚点；无独立探针=质量靠自觉

### 选项 B：仅定义文档（人读文档执行）
- 优点：权威清晰
- 代价：对 agent 是建议不是约束（宪法 C2 反面）；每次执行手工对照，必漂移

### 选项 C：六件套——定义文档（SOP 权威）+ 制品模板 + 目录约定 + 名词表 + skill（执行形态）+ 探针（验收）；冲突以定义文档为准并回修 skill
- 优点：权威/执行/验收三权分立；模板单一来源堵漂移；每阶段建成即在平台自身实跑（自举验证）
- 代价：一个阶段五~六个文件，维护面大（靠"同 PR 改"纪律+探针互查缓解）

## 决定

选 C。决定性理由：用户明确指令 + 阶段0/1 双实证（漂移与语义缺口分别被探针/SOP 抓获）。

## 后果

- ✅ 阶段能力可验收、可分发、可培训（六件套本身就是教材结构）
- ⚠️ 模板改动必须三处同步（模板/探针/既有制品）——纪律项，探针兜底
- 可复议条件：无（定式经两阶段实证；若 skill 机制官方大改则重估）
