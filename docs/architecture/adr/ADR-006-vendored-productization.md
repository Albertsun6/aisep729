# ADR-006：个人 skills 以 vendored 复制改造方式产品化

- 状态：accepted
- 日期：2026-07-31
- 关联：US-7 · SR-5 · 宪法 C9

## 背景与驱动力

平台整合既有个人 skills（req-discovery/feature-fullstack/debate-review/project-health 等），但平台仓必须自包含可分发。

## 备选方案

### 选项 A：软链/引用 `~/.claude/skills/`
- 优点：零重复，个人改进自动生效
- 代价：分发即断链；个人隐私内容泄漏风险；受众机器上根本没有这些目录——直接违宪 C9

### 选项 B：vendored 复制改造（复制进平台仓，去个人路径、统一 e2e-* 命名与模板、中文化）
- 优点：自包含（grep 探针可证）；平台版独立演进不受个人版影响；改造过程即产品化打磨
- 代价：与个人版分叉，好改进要手工双向搬运

### 选项 C：抽公共包（个人版与平台版共同依赖一个 skill 库）
- 优点：理论上最优雅
- 代价：为 7 个 skill 建包管理体系=典型过度抽象（宪法 C2 简单优先精神；单人维护成本不成立）

## 决定

选 B。决定性理由：C9 自包含是分发底线；C 是没人要的灵活性。

## 后果

- ✅ SR-5 grep 探针可执行证明自包含；平台版按受众打磨不迁就个人习惯
- ⚠️ 分叉维护：约定"平台版为产品正本，个人版按需回搬"，不承诺同步
- 可复议条件：skill 数 >15 或出现第三方贡献者时重估 C
