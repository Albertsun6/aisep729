# PR-FAQ：solo-first（超级个体一等公民：门禁拓扑重设计 + 产品论题反转）

> 阶段 0 产物 · 门禁⓪（立项/下注）评审材料 · 2026-08-01 · 模板见 docs/process/stages/stage-0-discovery.md
> 状态：**待批**——本立项含产品论题级变更（定位反转），门禁⓪必须由人亲自裁决，agent 不代录（2026-08-01 会话已裁"立项走 (b)"，但 go/modify/kill 应基于你读到的本文）

## 假设陈述

For **超级个体**（一人+AI 承担立项到退役全链路的开发者与独立顾问）, who **需要企业级质量治理、却没有第二个人来当评审者与批准人——现有一切研发治理框架都默认多人组织**, the **solo-first 形态** is a **平台的目标形态重定位（企业多人模式降为 scale-out profile）**, that **把人审收敛到判断项、机器审最大化、跨模型异构评审补盲区、签字语义写准——让一个人也能产出可审计、可交付的企业级质量**。

## 最险假设（RAT）

**假设**：超级个体**愿意用**"对自己狠"的治理——单人没有外部强制，动力只能来自交付可信度需求；若目标用户不买账，定位反转不成立。
**最便宜验证**：找 2–3 个单人开发者/独立顾问照 README 从零跑一遍（顺带补掉"无真人冷启动验证"这条已知限制），观察窗两周内看是否有人走完一条 feature 全链。

## 未来新闻稿（写给成功那天）

**「一个人跑完六道门禁：AISEP729 solo-first 形态发布」**

平台完成定位反转：超级个体是目标客户。门禁按清单项拆成机械项（全部转可执行断言）与判断项（人保留极短授权签字，语义="确认机器断言全绿并接受残余风险清单 X"）；跨模型异构评审作为"第二认知视角"配上强制机械保障（prompt 模板入库、原始输出存档、重试留痕）。首批非作者用户跑通完整链路，"只有一个人跑过"的已知限制被划掉。

## 客户与痛点

**买单者**：超级个体本人（工具采用）；间接为其客户（交付可信度）。
**痛点**：2026-08-01 评估实证——platform-pilot 六门禁同日批完、19 分钟连过三门、"人类逐项确认 15 项 PRR"实际 14 分钟签完。不是人偷懒，是**企业形态的核对类仪式在单人场景必然退化为签字剧场**；而现有流程没有为"没有第二个人"提供正式形态，只能降级运行。

## 差异化主张

壁垒：判断/机械二分与"强制力只能来自可执行断言"已被本仓 142 条负样本与两轮异构评审实证支撑，不是理念是工程。为什么是现在：platform-hardening 刚把地基假绿拔完（探针可信了），拓扑重设计才有意义；AI 能力拐点使"一人全链路"从口号变为常态。

## 方案草图（可选，简单 feature 并入新闻稿）

一份 ADR-016 + 配套修订，设计原则（经 2026-08-01 两路异构评审修正钉死）：
① 颗粒度到清单项：逐项标 mechanical/judgment，机械项转断言，判断项保留人签，签字语义改写为"确认机器断言全绿并接受残余风险清单"；② 门禁①②合并的两个候选形态（一次人操作两个命题 / 正式合并为 Definition 阶段）在 ADR 内对比裁决；③ 冷静期与异构评审**并联**（防不同失效：模型盲区→异构；同 session 签字污染→最小间隔/跨 session 签批）；④ 异构评审=第二认知视角**不是第二批准人**，唯一人类 owner 承担全部归因（C14 不破），配最低机械保障；⑤ 显式修宪依赖：动 C12/C14 措辞须独立 ADR（check-constitution-adr.sh 已看守）；⑥ C8 微改动轻量通道正式化（platform-hardening 已实跑过一次：prfaq+经评审的行动计划代 tasks）。
产品侧：修订 specs/platform-pilot/prfaq.md 的假设陈述与 RAT（重批走 check-gate-immutability 的重批留痕机制）；企业模式改写为 scale-out profile 文档。

## Appetite（投入上限，熔断线）

**两个工作日（复杂度 16 点：ADR-016 8 点 + prfaq 修订与 SOP/探针适配 8 点）**。到期砍范围保交付，不展期。砍序：先砍 SOP 全量适配（ADR 先立、SOP 分批跟）→ 再砍企业 profile 文档 → 保 ADR-016 与 platform-pilot prfaq 重批。

## 深坑（Rabbit Holes）

- **"人审最小化"滑坡成"没人审"** → 绕行：先枚举判断项清单再机器化机械项，④⑤的授权签字任何方案下保留（评审 G8/S4 已钉）。
- **修宪流程自锁**：改 C12/C14 需 ADR，而裁决人只有一个 → 绕行：修宪 ADR 走冷静期 + 异构评审双保障，留痕给未来审计。
- **咨询叙事受损**（企业客户看到"默认单人"）→ 绕行：企业 profile 文档同步产出，销售叙事="从超级个体到团队同一套治理"。

## 不做什么（No-gos）

- 不动门禁③服务端模型（PR 合并+required checks 仍是唯一权威）
- 不做多人协作/审批流功能；不为迎合"单人"拆除任何确定性探针
- 不在本 feature 里实施 L1 存活性迁移（评估 C2，另行立项）

## FAQ

**Q1：这是不是给"自己批自己"洗白？**
不是。C14 不动：判断项签字仍是可归因人类；变化是把"假装人核对了 15 项"的签字剧场，换成"机器核对 15 项、人签残余风险"的真实语义——签字更少但每个都是真的。

**Q2：为什么定位反转要走门禁⓪而不是顺手写进 ADR？**
战略评审（S6）钉死：产品论题变更不得夹带在工程 ADR 里——prfaq 的 RAT 与假设陈述是立项契约，改它=重新下注，必须人裁。

**Q3：企业模式还卖吗？**
卖，作为 scale-out profile：同一套真相层与探针，多人时把批准移到服务端 review 事件（approver≠author）。反转的是默认形态与目标客户叙事，不是能力删减。
